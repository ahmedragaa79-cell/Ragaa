# Local storage · Phase 2

Strata stores outlets on **one device**. There is no server, account, API, synchronization or app-managed cloud backup. The first open creates the schema, not business records. A successful write is reported only after SQLite completes it. The preferences plugin remains separate and never stores an outlet or a balance.

## Where the database lives

These are platform-resolved locations, **not** hard-coded example container UUIDs. Changing a package/bundle ID, OS user, browser profile or web origin can select a different workspace. Keep installation identity and origin stable across upgrades.

| Target | Location / implementation |
| --- | --- |
| Android | `Context.filesDir/strata.sqlite` in the app sandbox, typically `/data/user/0/<applicationId>/files/strata.sqlite`; Android automatic app backup is disabled in the manifest. |
| iOS | `<app data container>/Library/Application Support/strata.sqlite` via Foundation. The container path is not a public Documents path. |
| Windows | `%LOCALAPPDATA%\Strata\strata.sqlite`, **not** Roaming AppData or the working directory. Missing local profile storage is an error. |
| macOS | Application Support + bundle ID, inside the current sandbox: typically `~/Library/Containers/<bundle-id>/Data/Library/Application Support/<bundle-id>/strata.sqlite`. |
| Linux | `$XDG_DATA_HOME/<application-id>/strata.sqlite` (default `~/.local/share/...`); `path_provider_linux` can use the executable name for legacy/fallback installations. |
| Web | Per **origin and browser profile**. Logical database `strata`, file `/database` inside SQLite's virtual filesystem. Preferred OPFS `drift_db/strata/`; otherwise shared-worker IndexedDB database `strata`. Not a localStorage JSON document or a downloadable file. |

Five native targets use `NativeDatabase.createInBackground` and sqlite3's native build hooks. Build-time tools may need network access to fetch packages/binaries; the installed app does not. Keep the desktop bundle together with its native assets. OS/user-managed device snapshots, enterprise policies and third-party backup software are outside the app's control. SQLite is not additionally encrypted by this app.

## Schema and invariants

`PRAGMA user_version = 2`. One business table: `outlets`.

| Domain → SQL | Rule |
| --- | --- |
| `id` | Non-null TEXT primary key, generated UUID v4. Never regenerated by an edit or status change. |
| `outletCode` → `outlet_code` | Required trimmed TEXT, UNIQUE with SQLite `NOCASE`. An inactive outlet still owns its code. Spelling/case is preserved; ASCII case variants conflict. |
| `name` | Required nonblank TEXT; input trimmed. Names need not be unique. |
| `description` | Nullable TEXT. Blank input becomes NULL, including when clearing a description during edit. |
| `isActive` → `is_active` | Boolean stored as INTEGER 0 or 1, checked, defaults to active. No delete operation. |
| `createdAt`, `updatedAt` → `created_at`, `updated_at` | Non-null UTC epoch milliseconds. Same initial stamp; only `updated_at` changes on edits/status writes. Display uses local time and current interface locale. |

Repository writes are atomic single SQL statements. SQLite enforces uniqueness even if two requests race. The UI localizes required/duplicate/not-found/storage feedback and retains unsaved input after a failed save. Search binds and escapes the input; `%`, `_` and `!` are literal text. SQLite `LIKE` handles English ASCII case and Arabic substrings, not accent/diacritic folding. List order is `name COLLATE NOCASE, id`. The unfiltered count projection is a separate watched aggregate; filtering never changes dashboard counts.

### Opens, migrations and failures

- The first Riverpod database consumer opens one shared connection. Screens distinguish loading, error and a genuinely empty directory. A retry discards the **connection**, never the data. Unknown SQLite errors are not displayed verbatim with paths/parameters.
- A new empty database creates all schema objects transactionally. v1 is the base directory schema; v2 adds the `(is_active, name COLLATE NOCASE, id)` index transactionally and idempotently. Phase 1 had **no** installed SQLite database to convert. Tests open a populated v1 fixture and inspect it after close/reopen.
- Reject unversioned nonempty tables, unsupported upgrades and future versions, enable foreign keys, run `PRAGMA quick_check(1)` and read the expected columns before making the repository available. No reset, automatic repair, deletion, forced downgrade or volatile replacement. `quick_check` detects integrity problems; it cannot detect every semantic error in data.
- Future changes must add explicit forward steps, keep stable IDs/history, and test prior on-disk fixtures before release. On corruption, retain the original bytes; check disk space, permissions and app version. Never clear app/site data to fix a read error.

### Offline browser delivery

Serve the packaged `build/web` at a stable HTTPS origin (loopback HTTP for testing); serve `.wasm` as `application/wasm` and allow same-origin workers, IndexedDB/OPFS and service workers. Bundle local CanvasKit with `--no-web-resources-cdn`, then run `python3 tool/prepare_offline_web.py`. This last step packages an atomic, versioned **static app shell**. Its worker caches public executable/assets only, never the business database. Allow the first install to finish online before disconnecting. A new shell waits for previous clients to close; an unfinished install does not replace the active shell. Serve the worker and index with revalidation. `flutter run -d chrome` is a development server, not an offline installation.

Wasm and worker files in `web/sqlite` are from `simolus3/drift` release `drift-2.35.4`, matched to `sqlite3 3.9.1`. `tool/fetch_sqlite_web.sh` verifies both release SHA-256 digests when updating the vendored pair. They are **not fetched at runtime**. `WasmDatabase.probe` selects `opfsShared`, `opfsLocks` (requires COOP `same-origin` + COEP `require-corp`), or `sharedIndexedDb`, in that order, preferring an existing storage API. An ambiguous existing store or no safe durable option is an error. Neither in-memory nor race-prone `unsafeIndexedDb` is an accepted fallback. Do not change origins or disable a previously used storage API when deploying a new build.

Storage is subject to browser quotas, eviction, clearing site data and private-mode lifetime. Avoid private windows and embedded contexts with restricted/partitioned storage. A first-ever visit cannot load offline; losing the shell cache requires reconnecting to reload assets, not rebuilding the database. There is no browser-independent guarantee against data loss. Chrome's release test uses a fresh temporary profile, checks the actual storage API, writes via the UI, reloads, closes Chrome, and reopens the same profile **offline** to edit and reload again.

## Manual backup and restore — design only

**No export, import, backup UI, scheduled job, or cloud copy is implemented.** For a future separately approved tool: on explicit request use SQLite's consistent snapshot/backup facility (or quiesce connections and verify a clean, closed database); do not copy a live database file without its committed journal/WAL state. Offer a user-chosen local destination/download with schema/app version, timestamp and checksum. Treat it as sensitive data. On web use a supported worker snapshot/file download, not a dump of arbitrary IndexedDB object stores. Restore into a separate temporary database, check the checksum, supported version, integrity, constraints and counts, run tested upgrades there, then close connections and require confirmation before swapping. Preserve the original and a rollback copy; abort without replacing anything on failure.

## Future revenue (not in this schema)

A future revenue row should reference `outlets.id` (**not** name or code), carry its business date, shift number constrained to **1 or 2**, amount with agreed precision, creation timestamp and optional recorder identifier. Enforce `UNIQUE(outlet_id, business_date, shift_number)` and referential integrity in SQLite. Recheck outlet eligibility in the same write transaction: inactive outlets remain visible in historical joins but are not choices for *new* revenue until reactivated. Confirm currency/scale, business-day boundaries and corrections before implementing writes. No revenue table, monetary total, PDF or spreadsheet is produced now.
